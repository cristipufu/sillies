# Sillies development

- Treat reviews of other products as inspiration for an independently designed implementation. Do not copy their source or vocabulary tables. Keep the names of products used as inspiration out of feature code, comments, documentation, and commit messages.

- Retain local diagnostics only through an injected `DiagnosticSink` and typed, content-free events. Events in that archive must never include messages, prompts, audio, clipboard/Vault content, window titles, paths, raw error descriptions or arbitrary dictionaries. Record transitions and first-delivery milestones, never audio packets, tokens or animation frames. The app owns the bounded recorder; journal I/O stays off the main queue, shutdown flushes through the modal-safe delivery path, and exports preserve size/privacy bounds. Keep rotation, retention, failure/retry, concurrency and export regressions in `SilliesDiagnosticsTests`; see `docs/contributing/diagnostics.md`.

- Keep behavior and geometry in `SilliesCore`, free of AppKit and timers.
- Localize interface copy with native SwiftUI literal labels or `String(localized:)`; keep complete sentences and native placeholder types. Language catalogs live in `Localization/*.json`. Update all shipped translations and plural forms; `make check` verifies coverage, formatting, and source extraction. Never translate runtime IDs, model prompts, user content, or canonical persisted speaker markers. Use `LocalizedCatalogText` only for explicitly extracted bundled display fields.
- Theme contributions live in `Sources/SilliesDesign/Themes/*.json`. Keep discovery and validation off the main actor. Inject the app-owned `ThemeEnvironment` into presentation roots through required parameters; only app composition creates it. Never add fallback theme owners or default theme arguments in production. SwiftUI reads immutable `SilliesTheme` values through its environment and native artwork receives them explicitly. Never add shared theme preferences or an unthemed hosting root. Use semantic colors and paired button/selection foregrounds; preserve drafts, selection, and reading position when appearance changes. Adding a language or palette must not require a Swift registration switch. See the localization and theme contribution guides.
- Own local reasoning in `App/Composition`; inject `LocalReasoning` into consumers. Never add shared reasoning/model-environment instances, service locators, or default live backends. `SilliesReasoning`, `SilliesVault`, and `SilliesWriting` enforce reusable feature boundaries; the architecture checker validates imports and `Package.swift` dependencies for new files and targets. Do not widen a policy to bypass a failed boundary check.
- Keep long-lived Chat reply preparation bounded by the selected model profile: one checkpoint read and one recent page, with measurement-only `ConversationBudgeting`. Never walk the archive or generate summaries before replying. Checkpoints run as one-page, one-generation background slices that yield to interactive inference and stop with their Chat lifetime. Persist them using generation/revision comparison; UI saves must preserve the current checkpoint. Keep complete messages searchable, and validate scale, restart, stale writes and native cancellation with bounded headless controls.
- Keep Chat orchestration in `SilliesChat`, synthesis contracts in `SilliesTTS`, and audio-device ownership in `SilliesVoicePlayback`. Voice inference belongs in the killable `SilliesTTSInference` helper; `SilliesFishSpeech` and tensor SDKs must never enter the app or feature targets. Reuse existing native runtimes or focused app-owned implementations; do not add Python or community TTS runtime packages. Await audio sinks for backpressure, preserve written replies on voice failure, and finalize microphone words before saving. Model capability lists must describe the supported runtime without promoting one language over others.
- Voice preparation must use non-preemptive inference admission and provider-owned voice caches. Keep model retention in the registry with explicit conversation lifetimes and memory-pressure eviction; helpers must not independently expire a retained runtime. First-audio latency comes from non-silent device presentation, never buffer scheduling. Preserve bounded phrases, cancellation, rendered echo reference, and playback backpressure when optimizing speech.
- Vault listings contain bounded `SessionRecordHeader` pages. Load full records by ID, keep detail caches byte-bounded, and queue background work by ID. SQLite is the initial Vault format; no pre-release JSON archive migration is required. Body/header/search changes share a transaction, and failed writes retain their recovery payloads. UI/background edits use `VaultRecordEdit` against the latest record, never whole-record replacement from a view snapshot. Notes and OCR completions must carry their processing revision. Use stable cursor pages and changed-ID invalidation; unrelated saves must not restart selected-detail loads.
- Character-specific event responses belong in JSON, not conditionals in the controller.
- Keep platform event producers, behavior selection, artwork, and clips separate.
- Strictly follow Robert C. Martin's *Clean Code* principles across all modules:
  - **Functions (Ch. 3)**: Keep functions small, focused on doing one thing at a single level of abstraction, and free of unused parameters. Group cohesive arguments (>3–4 parameters) into parameter/context structs (`WindowServerSource.Request`, `SkillTickContext`, `SkillFinalizeContext`, `DropBindingContext`). Never use boolean flag parameters that split a function into two behaviors; expose intention-revealing methods or enums instead (`CompanionView.PresentationMode`, `resetAndHideOverlays()` / `resetAndCloseOverlays()`).
  - **Classes, Files & Encapsulation (Ch. 6 & Ch. 10)**: Enforce Single Responsibility Principle (SRP) per type and per file. Keep domain state mutations encapsulated on the owning type (`CompanionInstance` owns its motion, pickup, and surface-detach state transitions; `AutomatedLaunchRunner` owns CLI/GUI test dispatch outside `AppDelegate`) and respect the Law of Demeter (delegate through the immediate collaborator instead of chaining across internal stores or layer trees).
  - **DRY — Eliminate Duplication (Ch. 17 G5)**: Maintain one source of truth for window-entry dictionary parsing (`WindowServerSource.ParsedWindowEntry`), screen visible-frame fallbacks (`CompanionPanel.visibleFrame`), unit-test detection (`CompanionPanel.isRunningUnderUnitTests`), hit-test stack traversal, and expiring-binding ticks. Never copy-paste multi-line state resets.
  - **No Magic Numbers, Positional Subscripts, or Stringly-Typed State (Ch. 17 G25)**: Extract layout dimensions, thresholds, audio/DSP parameters, and timing constants into named `static let` constants. Index batched AX attribute arrays through typed enums (`InspectedAttribute`), and represent UI/domain conditions as model properties (`SessionRecord.requiresPermissionAccess`) rather than ad-hoc view string matching.
  - **Error Handling (Ch. 7)**: Never silently swallow persistence or I/O failures with bare `try?`; centralize atomic writes and log diagnostic errors to `stderr`.
- Character entry/exit/reattachment choices belong in pack transitions. Behavior clips, finite presentation transitions, and hit testing have separate owners. Character or animation additions must not require edits to window tracking.
- Transparent panel regions and native window drag/resize borders must pass input through, including in Play mode. Stop interaction monitors when paused, excluded, or disabled.
- Use Swift 6 concurrency checks. AX access belongs to the isolated worker; do not block the main actor on another application. Use `AXUIElementCopyMultipleAttributeValues` to batch per-window attribute reads into a single IPC call, and never re-query AX window hierarchies on `kAXMovedNotification`, `kAXResizedNotification`, `kAXTitleChangedNotification`, or `kAXSelectedChildrenChangedNotification` (which would stall the target application's main thread during window drags).
- Do not introduce per-companion timers, screen-sized animated overlays, pixel/screenshot polling, or per-frame SwiftUI state updates. Window metadata reads must be bounded, confined to a worker, and target the known focused window during manipulation (`discover: false`). Never allow a queued `discover: true` request to override single-window reads while manipulating a window.
- Keep drag attachment synchronous with native frame changes or display-linked pointer movement. Asynchronous metadata validates foreign-window gestures; it must not drive each drag frame. Measure live attachment error during manipulation, not only after settling. Do not start ambient `.stroll` or `.hop` motion tweens while a window is actively moving or resizing (`isManipulatingWindow`).
- Enforce frame budgets structurally via `InteractionSmoothnessMetrics` and `SmoothnessBudgetTests` across all four interactive paths (`windowMove`, `windowResize`, `windowSwitch`, `companionDrag`). Never call `setFrame(..., display: true)` on companion or skill overlay panels, never use `CAShapeLayer` for window-sized drop outlines (use hardware-composited `CALayer` borders and prestage badge layout at pickup), never read `workspaceMotion.presentation()` during live manipulation, place each companion at most once per `updateSurfaces` pass, and keep companions visible while async application-switch window discovery (`isAwaitingApplicationWindow`) is in flight.
- A title-area mouse drag is only a candidate: require independent window movement before pointer prediction, and never block focus or window-lifecycle notifications while `isDragging` is false. Failed/custom-toolbar drags must never move companions or their exclusion mask. Anchor custom-toolbar threshold adjustments to the pointer sample nearest `capturedAt` (never `now`), interpolate sub-frame pointer segments during high-velocity drags, and keep the active `currentWindowID` exempt from minimum-size or lagging-AX-frame disqualification only during active move and resize gestures (`isManipulatingWindow`). Inspect `kAXMinimizedAttribute` in `AccessibilityWindowSource`, preserve the last verified `roleSnapshot` across transient AX read timeouts, snap `<= 6pt` WindowServer pre-stretch wobble to the canonical AX frame when idle, exclude interior child popups (such as browser URL/search omnibox overlays) contained inside a larger normal-layer window of the same process, and never fall back to unverified candidates when `roleSnapshot.hasVerifiedWindowList` is true so Dock genie minimize animations never move or double-fade companions. Refresh `AccessibilityWindowSource` upon window-drag release reconciliation.
- In Play mode, opaque character artwork wins over background windows (including headers, tabs, and URL bars) while transparent panel regions pass input through (`CompanionInteraction` must require `containsInteractiveArtwork` whenever the pointer is inside `panel.frame`, and attached `.top`/`.desktop` panels must crop horizontal width to `AttachmentPose.designCanvasSize * size / 100`). Match `CompanionPanel` and HUD window levels to the attached window's z-layer (`normal + 1` on normal windows so floating PiP windows occlude them, and `floating + 1` when attached to a floating window or picked up). When picked up and dragged, companions render unclipped above the focused window.
- Preserve distinct normalized slots when returning from an unavailable surface; do not collapse every companion to the midpoint of a degenerate path.
- Companions belong outside the focused window. Never lower a top perch into document content to compensate for limited headroom. Use exterior sides or wait in the menu bar.
- Attached NSPanel bounds must exclude the focused window geometrically; a layer mask alone is insufficient for input isolation. Keep rig and transition pivots at the local contact offset when cropping the canvas.
- Every new long-lived producer must have an explicit stop path for pause, exclusions, and termination. When `applicationShouldTerminate` returns `.terminateLater`, deliver flush completions via `CFRunLoopPerformBlock` across `modalPanel` and `commonModes` (never rely solely on `@MainActor` `Task` / `DispatchQueue.main`, which AppKit's `NSModalPanelRunLoopMode` termination loop does not drain), and keep automated CLI/GUI check modes guarded by an off-main-thread watchdog timer.
- Use monotonic time for behavior, motion, and cooldowns.
- Keep character IDs and saved preference keys stable.
- Do not add telemetry, screen capture, keyboard-content collection, or network services without a product requirement. The user-authorized everyday-writing requirement permits explicit hotkey dictation, bounded selection editing, and destination validation/insertion. It does not authorize automatic keyboard-content or clipboard-history collection.
- Run `make check` for behavior/platform changes. Use `scripts/test.sh` for selected tests; required test, stress, and race runs must verify discovered-test completion receipts through `run-checked-tests.py`, never exit status alone. Use `swift format` for Swift source. Update extension docs when the pack schema or renderer contract changes.
- Keep performance measurements out of routine test runs. Classify timing budgets, large-scale fixtures and endurance tests by exact ID in `Tests/performance-tests.json`; run them on demand in release builds with `make performance-check` or `scripts/test.sh --configuration release --suite performance`. Functional failure/cancellation and fast structural-bound regressions remain standard debug checks. Native performance additionally requires explicit `--presentation gui` / `make performance-gui-check` authorization. Use `--bundle <test-target>` for focused compilation and discovery; never bypass completion receipts to shorten a run.
- Keep development artifacts bounded. After qualification, retain source, input/checksum manifests, raw results, completion receipts and reports; remove the disposable synthetic databases, derived indexes and backup/restore copies. Keep the current local app and at most one rollback bundle. Before cleanup, verify the exact generated paths and that no process uses them. Never sweep `build/` wholesale: it can contain ongoing work and reviewed previews. Installed models and the person's Vault are separate from build cleanup. See `Benchmarks/Vault/README.md` for fixture retention.
- Treat native identifiers, external counts, and saved values as untrusted boundaries: use checked conversions and recoverable failure paths. Native window numbers must use `NSWindow.windowServerID`. Every crash fix needs a regression exercising its failure input; window activation, popover, or menu changes also require native workflow coverage, not just rendered-view tests. `make check`, `make stress`, `make race-check`, and targeted tests are headless by default. Classify native tests in `Tests/SilliesAppTests/execution-modes.json`; never bypass the test host’s presentation boundary. Visible activation, stacking and `--app-window-test` checks live in explicit `make gui-check` / `scripts/test.sh --presentation gui`; native frame timing lives in `make performance-gui-check` / `scripts/test.sh --suite performance --presentation gui`. Run visible checks only when the user explicitly requests them; otherwise report that coverage as not run.
