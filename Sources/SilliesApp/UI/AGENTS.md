# Native and SwiftUI presentation

Views render presentation models and forward commands to their owner. Do not perform synchronous file/image loading, audio processing, or AX/window-list queries here. Keep transcript rendering in its native viewport with incremental updates. Reading/selection must remain stable; following resumes on Jump to latest or returning to the bottom. Coalesce audio progress through `AudioSessionUpdateDelivery`, preserving lifecycle event order.

Conversation clarification cards render validated, saved question data; never parse choices from generated prose or hold inference while waiting for a person. Starters and choices preserve existing drafts. Conversation search and navigation need separate cancellation identities; export uses bounded pages and modal-safe progress/shutdown delivery. Message-size changes preserve native selection and IME composition. See `docs/contributing/conversation-interface.md`.

Routine Chat utilities (Memories, conversation search, Vault selection and memory editing) navigate inside the existing bubble through `ChatWindowNavigation`; do not add native sheets over its transparent shaped window. Preserve the mounted conversation, draft, viewport and native selection while concealing its text views and releasing hidden first responders. Keep availability and capture ownership on the stable session root. Validate native window identity, absence of attached sheets, and focus/selection restoration with `ChatPageNavigationTests`, not only view snapshots. Native export choosers and destructive confirmations remain explicitly scoped modal actions.

Keep header, finish controls, the selected reading pane, and footer visible at minimum size. Audio details keep the language picker fixed; Participate uses separate Transcript and Meeting suggestions panes with independent scroll viewports. Retain the native transcript and its reading/selection state when switching panes, and prevent the concealed transcript from retaining keyboard focus. Never nest suggestion scrolling inside another scroll view or wrap the live transcript in `ViewThatFits`. Long diagnostics belong in the shared recovery presentation, without displacing the reading pane. Suggestion bubbles measure text when content/available width changes and preserve native z-order and input pass-through during movement.

Example: a new transcript status is a presentation-model property, not view-level string matching. A vault action belongs in `SessionVaultModel`; a view invokes it instead of editing stores directly.

Run `LiveTranscriptTests`, `SkillInterfaceTests`, `MeetingSpeechBubbleTests`, `SessionVaultModelTests`, `make stress`, and `make check` as relevant. Use the opt-in UI snapshots for visual changes and inspect minimum-size, reading/selection, failure, and long-text states.

Live and saved session errors use `SessionFailureNotice`. Recovery actions come from `SessionFailure`, and `SessionRecovery` opens the corresponding permission pane. Keep partial transcripts and summaries visible alongside failures; never choose recovery by searching their text.

Register ordinary app content windows with `AppContentWindowStacking`: Settings, Vault, writing tools and transcript details cover normal-layer companion/HUD overlays while Sillies is active and return to their native level on deactivation. Keep ordinary content below native floating/PiP windows; a companion attached to a floating host stays with that higher native group. Activation callbacks own this transition; never fix layering with per-frame ordering or by making Settings permanently float above other apps. Dictation details remain nonactivating while participating in this foreground/background policy; opening them must never steal the insertion destination.

The recording control HUD and meeting suggestion bubble inherit their companion panel's actual native level and order immediately above that panel. Do not derive a higher overlay level from the target's layer: bound companions share the host's level so foreground application windows can cover them together. Keep layout preparation separate from presentation so level changes and sizing remain testable without showing windows.

Talk, Record, Listen and Participate share bubble artwork, control spacing and pure placement. Recording controls have priority over meeting thoughts: place the thought in free space, or conceal it while its suggestion remains available through the transcript button. Opening or dismissing a Talk transcript is a presentation action, never a mode change or capture cancellation. Explicit Chat/Talk selection belongs to the session owner; End voice and session teardown own microphone shutdown. Preserve native input-method composition, selection, and scrolling when adjusting Chat typography or the expanding composer.

Vault has one app-owned `SessionVaultWindowController`, model and hosted root. Route typed destinations through that owner; never rebuild the root on each open. The window delegate owns visibility and producer teardown. Keep full transcripts inline by default, with an explicit reusable pop-out. Parent native export choosers explicitly through `NativeFileDialog`; late callbacks must not finish a newer request. Settings deep links select the intended companion profile without reopening setup.

Pending export and discussion actions need request identities across persistence barriers; checking visibility alone is insufficient after close/reopen. Stop invalidates those identities before cancelling native choosers. Stash owns its retained browsing model in `StashPickerController`, with explicit resume/stop from native window lifecycle events; do not rely on SwiftUI disappearance to suspend a retained window. A browser may release only its own preview pin. Concealed Vault panes must disable keyboard actions as well as pointer input.
