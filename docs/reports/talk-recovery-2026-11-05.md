# Talk recovery and conversation attribution — 5 November 2026

The local release includes the voice-admission fix, tighter Chat typography and shared bubble corners, and Talk placement that respects the host window's horizontal edges. Apple name recall remains inconsistent. The changes below do not claim to solve that model behavior.

## Voice ownership

The observed “A voice is already speaking” error came from inference admission, not a second voice. A microphone recognition pass was still active when the reply's first spoken phrase requested synthesis. The registry treated that temporary rejection as `TTSError.busy`.

Synthesis now waits asynchronously for admission, then claims it again. It does not reserve the runtime ahead of recognition. Cancellation removes the waiter; a real user interruption can still cancel the old reply. A microphone event that produces no words can finish without turning the pending reply into a voice error. The existing exclusion for genuinely concurrent voice requests remains.

Regression tests exercise recognition overlapping the first phrase, cancellation while waiting, and the next turn acquiring the runtime. Device playback with a live microphone still needs user validation; synthetic admission tests do not establish acoustic echo performance.

## Presentation

- Chat body text is 14 pt, with 16 pt between messages and smaller padding.
- Chat, Talk and Record share a 16 pt outer corner policy. Message bubbles use 12 pt and the composer uses 14 pt.
- Talk, Record, Listen and Participate use the same native curved-tail bubble, with shared control spacing and padding. Recording keeps its transcript, pause, Finish and cancel actions; completion uses the same bubble surface.
- These controls reserve 16 pt between the panel and the companion's contact point, with further inset in the visible artwork. This was lowered from the initial 24 pt after visual feedback. Other task cards use a head offset of 0.68 of the companion size.
- When space permits, the controls fit inside the host window's horizontal extent. They open inward near either edge; a host narrower than the bubble falls back to the visible display bounds.
- Meeting thoughts use the opposite side or free vertical space to avoid the controls. If the screen has insufficient room, the thought is concealed; its suggestion remains accessible from the transcript button. This placement uses cached measurements.
- Native window updates supply the known host frame. Placement does not introduce Accessibility reads, timers, or per-frame SwiftUI updates.

## Apple conversation investigation

Read-only inspection of the reported conversations distinguished acknowledging a name in an introduction from recalling it later. Both companions could acknowledge the human's introduction. One conversation also contained a correct earlier recall, followed by speaker-identity mistakes and later privacy refusals. The relevant fact remained present in the saved context and memory.

The generated checkpoint subsequently repeated an assistant privacy refusal in its notes. That makes the refusal available in later contexts; it does not explain the first refusal by itself. Context notes are already marked as fallible source data, and native transcript entries preserve user and assistant roles. The checked requests were within their context budget. The refusal was returned as ordinary model text, not a framework guardrail exception.

A minimal Foundation Models probe, without Sillies tools, reproduced a speaker-attribution error in a live session and after restoring that session's transcript. A separate native probe seeded with an assistant refusal continued refusing. This rules out our transcript restoration as the sole explanation; it does not prove that every integration choice is optimal.

Apple documents transcript restoration through [`LanguageModelSession(model:tools:transcript:)`](https://developer.apple.com/documentation/foundationmodels/languagemodelsession/init(model:tools:transcript:)). Its [safety guidance](https://developer.apple.com/documentation/foundationmodels/improving-the-safety-of-generative-model-output) and [permissive transformation mode](https://developer.apple.com/documentation/foundationmodels/systemlanguagemodel/guardrails/permissivecontenttransformations) distinguish framework violations from refusals generated by the model. Guardrail settings were not changed.

## Bounded experiments

Seven synthetic scenarios cover visible names, refusal history, reconfirmation, a non-name preference, corrections, an unknown name, and a seeded saved name. They use the production conversation service and its five tools. The saved-name fixture also exposes its source statement in history, so it is an attribution test, not proof of retrieval from otherwise hidden memory.

| Configuration | Reviewed attribution and write behavior | Decision |
| --- | --- | --- |
| Current conversation prompt and greedy sampling | 6/14 | Reference for this investigation |
| Explicit permission to recall shared facts and stronger correction instructions | 5/14 | Reverted |
| Original prompt, top-p 0.9 and temperature 0.7 | 7/21 | Reverted |

These are narrow, manually inspected results from Codex, not independent human review or general benchmark scores. The first two configurations have two repeats; the sampling experiment has three. They do not establish a statistically reliable ranking. Some sampled answers also violated Talk formatting, which is outside the table's attribution/write scope.

Keyword checks alone accepted answers that contained the expected name while assigning it to the assistant, or mentioned the name while refusing the question. One candidate answer correctly named the human but made an unwanted memory write. Reviews account for these failures and bind to the recorded task evidence. Neither rejected experiment is enabled in the app.

## Summary improvement retained

The checkpoint prompt now focuses on supported human facts, shared plans and unresolved requests, keeps ownership explicit, and treats earlier notes as a fallible draft. Assistant claims about its own rules are not human facts.

Six synthetic summary cases were inspected with Apple and Gemma 4 E4B. The new prompt omitted the assistant's invented privacy rule in the tested case while retaining the human fact. Correction and empty-history controls also remained useful. This is bounded evidence for the prompt change, not a guarantee that every generated summary will be accurate. No name-specific output filter, transcript rewrite, or automatic model switch was introduced.
